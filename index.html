CLI vs MCP：Agent 工具调用架构的深度辨析与选型指南

发表于 2026-09-07 更新于 2026-09-08 分类于 Agent

引言：一场正在发生的架构之争

2025 年以来，AI Agent 领域爆发了一场关于工具调用架构的激烈争论。一方认为 MCP（Model Context Protocol）作为 Anthropic 提出的开放标准，将成为 Agent 连接外部工具的事实标准；另一方则提出”CLI 会取代 MCP”的判断，认为命令行工具配合 Skill 文档的模式在 context 经济性、可组合性和模型亲和性上具有本质优势。

这场争论并非单纯的技术偏好之争，它触及了 AI Agent 架构的核心问题：**大语言模型应该以何种方式与外部世界交互？**是通过标准化的结构化协议，还是通过灵活的文本命令？这个问题的答案将直接影响未来 Agent 平台的生态格局、开发者的接入成本，以及最终用户的体验。

本文以美团开放平台的真实 Skill 实践为切入点，完整拆解两种架构的交互流程，从七个维度进行系统对比，并结合第一性原理和历史类比，给出深度的选型决策框架。

**核心论点预告**：CLI 与 MCP 不是取代关系，而是分层关系。CLI 正在抢走"交互层"的主战场，而 MCP 在"连接层"的标准化与安全边界短期内不可替代。最终的收敛形态是"Skill 交互层 + 多后端适配层 + 服务层"的三层架构。
